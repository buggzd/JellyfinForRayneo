# Repository Guidelines

## Project Map

This repository contains a native Android app and two embedded React/Vite
frontends:

- `AndroidApp/`: lifecycle, sessions, WebView bridges, RayNeo display control,
  and JVM tests.
- `GlassesUI/`: catalog, details, HTML video/HLS playback, subtitles, and
  spatial focus (React + strict TypeScript).
- `CompanionUI/`: discovery, login, settings, diagnostics, and phone touchpad.
- `AndroidApp/app/src/main/assets/{GlassesUI,CompanionUI}/`: committed
  production bundles generated by the frontend builds.

Read `README.md` for setup and release workflows. Before changing sessions,
bridges, playback, diagnostics, remote input, or display modes, read
`docs/ANDROID_ARCHITECTURE.md`. Product scope lives in
`docs/JELLYFIN_FEATURE_ROADMAP.md` and `docs/Jellyfin-Web-Reproduction-Spec.md`.

## Architecture Guardrails

Do not add Unity, Cardboard, LibVLC, a native fallback player, or duplicate
native UI. The phone owns discovery and authentication; the glasses own
browsing and playback. `SessionRepository` is the sole native session source.
Validate and bound every WebView message, never expose secrets or arbitrary
server errors, and clear native and glasses state on logout or unauthorized
restore.

Preserve one glasses WebView and one HTML `<video>` in both `Mirror2D` and
`StereoVirtualScreen`. Only an active hardware-mode transition may hide the
WebView; failure must reveal safe 2D without automatic retries. Advertise
direct play only from the intersection of hardware `MediaCodec` decoders and
WebView support; otherwise use Jellyfin's H.264/AAC HLS fallback.

## Build and Verification

Use JDK 17+, Android platform 35/build tools 34.0.0, and the pinned RayNeo SDK.

```bash
./scripts/install-rayneo-sdk.sh
npm --prefix GlassesUI ci
npm --prefix CompanionUI ci
./scripts/build-android.sh debug
```

For focused frontend work, run `npm --prefix GlassesUI run check` and both
frontend builds. WebView changes require both builds, JVM tests, lint, APK
assembly, and `scripts/verify-no-unity.sh`. Device-facing changes also require
the regression matrix in `docs/ANDROID_ARCHITECTURE.md`.

## Code and Repository Hygiene

Use four-space indentation and Allman braces in Java; keep Android UI work on
the UI thread and network work on bounded executors. Follow existing React
functional-component and hook patterns. Name JUnit 4 fixtures `*Tests` and
tests after observable behavior.

Never commit credentials, LAN addresses, `.jellyfin-dev.json`, SDK binaries,
APK/AAB files, signing files, `local.properties`, build output, or absolute SDK
paths. Preserve unrelated edits, stage generated bundles deliberately, and use
focused Conventional Commits.
