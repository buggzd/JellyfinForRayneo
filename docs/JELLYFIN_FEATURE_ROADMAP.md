# Jellyfin 功能路线图

本路线图以 Jellyfin Web 的信息架构为基准，并针对 RayNeo Air 的远距显示、方向焦点和手机输入场景做取舍。眼镜端负责浏览与播放；服务器地址、账号、密码及复杂文字输入继续放在手机端。

## 已完成：原生 MVP

- 手机端局域网发现、手动地址、Quick Connect、密码登录、设置、脱敏诊断和触控板。
- 眼镜端首页、继续观看、下一集、最近添加、收藏、搜索、筛选、排序、分页和文件夹浏览。
- 电影、剧集、季和单集详情，以及季切换、相关推荐、额外片段、演职人员和媒体规格。
- 收藏与看过状态同步，播放进度恢复、上报及手动切换上一集/下一集。
- HTML 视频直放，按硬件 MediaCodec 与 WebView 能力筛选格式，不兼容时回退 H.264/AAC HLS。
- 音轨选择、文字字幕本地渲染、位图字幕服务端烧录。
- Mirror 2D、单 WebView SBS 立体虚拟屏幕，以及失败后的安全 2D 回退。

## P1：大型媒体库与输入体验

- 由手机输入搜索文本，并把结果与焦点状态同步到眼镜端。
- 首页、搜索和媒体库改为服务端分页，避免一次读取固定上限的数据。
- 增加类型、年份、评分和演职人员筛选，以及从演职人员/系列继续浏览。
- 为超长标题、空媒体库、缺失图片和大规模文件夹补齐真机回归样本。

## P2：剧集与播放队列

- 补齐缺失集提示、特别篇和跨季导航。
- 自动播放下一集、随机播放、播放队列和队列编辑。
- 加强播放结束、手动停止、异常中断和跨设备续播的一致性验证。

## P3：高级播放增强

- 播放前选择媒体版本与画质上限，并完善超多轨道的滚动菜单。
- 字幕样式、延迟调节、章节、缩略图进度条和跳过片头能力。
- 向用户展示更完整的 Direct Play、硬件能力筛选和 Transcode 失败原因。

## P4：账户与设备体验

- 多服务器和多用户切换、快速重连及会话失效处理。
- 手机端增加队列管理和完整播放控制。
- 继续扩充 RayNeo 真机上的焦点、长按、返回键和双显示生命周期测试。

每个阶段都需要前端检查、JVM/Android lint 和 RayNeo 真机验证；UI 变更应附浏览器与真机截图。测试数据不得包含局域网地址、令牌或真实凭据。
