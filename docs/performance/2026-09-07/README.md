# 保留视觉效果的性能优化与真机复测

> 历史实测：数值、验证范围和构建方式对应文中版本。已实施措施与后续工作见 [性能维护](../../PERFORMANCE.md) 和 [功能路线图](../../JELLYFIN_FEATURE_ROADMAP.md)，不要把本报告的建议直接当作当前待办。

日期：2026-09-07。依据 [9 月 6 日报告](../2026-09-06/README.md)，本次实施代码优化并重新采样。对照源码为采样开始时 `main` 的 `67662d5`，包含后续 simpleUI Hero 和教程样式，不能把旧报告全部数值直接当成本次修改前基线。

48 组资源对照及两条 FrameTimeline 轨迹测试了 `67662d5` 与性能提交 `ce3a551` 对应的 APK。提交阶段另集成 `main / b541793` 的详情封面对齐更新，保留其样式，重新构建并补做合并后的真机检查；见 [integration-validation.json](integration-validation.json)。合并后两端构建、25 个前端测试、80 个 JVM 测试、Debug/Release lint 与 APK 检查再次通过；真机首页、详情页及 2D/SBS 切换正常，simpleUI 静态 SBS 的补充 10 秒样本仍为 0 绘制帧、CPU 约 0.29%。合并后没有重跑全部 48 组，以下主表仍对应原先列明的两份 APK。

## 已完成的改动

1. **淡出结束后暂停不可见装饰。** 保留播放器音柱的高度动画、光晕和圆角；保留触控提示的波纹。等待根元素实际 CSS 转场完成且 opacity 为 0 才暂停，重新显示时在绘制前恢复 CSS 播放状态。快速打断淡出、视频暂停及不支持动画检查的旧 WebView 均有处理。
2. **SBS 随内容更新绘制。** 删除 `StereoMirrorLayout` 无条件的 `postOnAnimation` 循环，由 WebView 子节点失效通知更新两眼；180 ms 深度/尺寸动画仍主动刷新几何。静态内容可以休眠，播放时仍由视频更新驱动。
3. **减少强制 WebView 图层。** 手机和 2D 使用硬件加速窗口下的普通绘制；只有已应用 SBS 时保留一个硬件 View 纹理，供左右眼共同采样。`LAYER_TYPE_NONE` 表示不额外强制整 View 图层，并非软件渲染。
4. **核验模糊后保留现有管线。** 当前 WebView 大半径高斯模糊已使用降采样近似，GPU 还有分离滤波和合并采样，CPU 后备具有三次盒式近似。本机 GPU trace 也捕获到对应调用。详见 [底层核验与固定版本源码](blur-audit.md)。没有降低半径、分辨率、阴影、折射颜色或可见动画频率，没有加入自定义 Kawase、背景截图或第二个播放器。

## 条件与测量范围

- 同一小米 `2509FPN0BC / SM8850 / Android 16`，WebView `150.0.7871.181`，连接实际本地 Jellyfin 和 RayNeo。2D 为 1920×1080，SBS 为 3840×1080，均约 60 Hz；眼镜 DOM 为 1440×810，默认对照深度 1、大小 95%。
- 两版均为源码构建的 debug APK、production 前端包；保留现有登录。APK SHA-256、全部 **48 个有效资源采样窗口，共 18.85 分钟**见 [measurements.json](measurements.json)，分组范围见 [summary.json](summary.json)。运行轨迹和功能检查另计，不混入 CPU/GPU 主表。
- 两套主题的 2D 首页静止/方向导航各两轮，20 秒/窗口，顺序 A/B、B/A；SBS 首页每主题一次。导航采用同样的原生方向命令和首卡焦点。可见循环动画一直保留；截图固定相位仅在资源采样之外进行。
- 同一个 MP4 HEVC Main 10、3840×2160、约 60 fps、约 3.54 Mbps 的 SDR 样本；每版、每模式、每主题两段 30 秒。从第 60 秒定位，预热 6 秒后采样；手机在触控板。
- HLS 另用同一个 MKV HEVC Main 10、1080p23.976、约 1.66 Mbps、带 ASS 字幕的 SDR 样本；手机实际接收 H.264/AAC HLS，各条件一次 20 秒。它不是原报告的 AV1 样本。
- CPU 为应用及关联 WebView renderer 合计，100% 表示一个核心，不含系统合成器或独立 codec 服务；GPU 为整机 KGSL 忙碌率，包含系统背景。**这不是电池功耗测量。** PSS 受缓冲、图片和 GC 历史影响，不作为固定内存预算或泄漏结论。
- 充电、系统默认 DVFS，未锁频；采样温度 32.6–36.5°C，thermal status 均为 0。两版分先后安装，温度未严格匹配；以下是本机重复短窗口结果，不是跨设备显著性结论。0 绘制帧时的 `4950 ms` 空直方图占位已改为 null。

**静态 SBS 的冗余绘制已消除。** simpleUI 首页 CPU 降约 97%，暂停视频 CPU 降约 94%；整机 GPU 回落到约 9% 的本机背景水平。两种 SBS 静态窗口的应用 HWUI 帧数从 2,438 / 2,444 降为 **0**。本轮暂停窗口按播放器默认行为显示静态控制栏。

**液态玻璃首页没有获得大幅降耗。** 它的状态点、滚动提示、手机触控入口继续循环，导航 CPU 也基本不变。simpleUI 导航 GPU 有下降趋势；不能用这些结果宣称所有页面普遍提速。没有采用旧报告中“把可见循环改成有限次”的建议，因为用户要求保持现有 UI 效果。

液态玻璃 2D 4K60 的 CPU 中位数下降约 **16.4%**，整机 GPU 下降约 **22.1%**；simpleUI 2D 4K60 的 CPU 基本不变，GPU 下降约 **21.6%**。液态玻璃 4K60 每 30 秒眼镜页面布局次数由约 **1,820 降至 114**；播放器剩余的进度/字幕更新继续正常运行。这支持将 CPU 收益归于移除了隐藏音柱引发的布局，而不是删去可见效果。

SBS 的 simpleUI 4K60 CPU 没有降低，且略有上升；GPU 也基本不变。24 fps HLS 则可以减少原来无条件按 60 Hz 提交的重复绘制：SBS simpleUI CPU 约降 18.7%，GPU 约降 21.4%。不把所有变化合并成一个“整体提升比例”。

| 4K60 条件 | 修改前丢帧范围 | 修改后丢帧范围 |
| --- | --- | --- |
| 2D 液态玻璃 | 1.32%–1.49% | 1.32%–1.71% |
| 2D simpleUI | 1.32%–1.48% | 1.32%–1.48% |
| SBS 液态玻璃 | 1.65%–1.69% | 1.21%–1.38% |
| SBS simpleUI | 1.59%–1.81% | 1.15%–1.16% |

丢帧由 `getVideoPlaybackQuality()` 增量计算，表示 WebView 视频计数，不是眼镜光学 FPS。**没有修复所有 4K60 丢帧，也没有证明 2D 丢帧改善**；SBS 短窗口有改善趋势，仍约 1.15%–1.38%。优化后四段 HLS 共 1,933 帧、零丢弃；修改前 SBS 液态玻璃窗口有 1 帧丢弃。全部正式播放窗口无 `waiting` / `stalled` 事件、结束 readyState 为 4。

DirectPlay 的实际视频 codec 是 `c2.qti.hevc.decoder`；HLS 是 `c2.qti.avc.decoder`，CDP 同时报告平台视频解码。每次起播与双眼抽样均只有一个硬件视频资源、一个 HTML video。HLS 保留原字幕处理路径，未开启烧录。补充检查发现这条 ASS 样本的 DeliveryUrl 返回约 3.22 MB 的非 WebVTT 内容、没有时间箭头；播放器显示字幕加载错误，不能把它记为字幕显示通过。相关 URL 选择及解析代码与基线相同，本次未修改，见 [字幕兼容记录](subtitle-compatibility.json)。建议另行修复：规范化 Jellyfin 字幕交付格式并验证实际内容，不能只依据所选轨道判断字幕成功。没有扩大硬件能力声明或取消 H.264/AAC 回退。

## SBS 呈现轨迹

额外采集同一 simpleUI / HEVC 4K60 / SBS 片段的两条 Perfetto 轨迹，顺序为优化版→基线版；128 MiB 缓冲，均覆盖约 20 秒，未出现非零解析错误或数据丢失计数。单独统计眼镜窗口，详见 [frame-timeline.json](frame-timeline.json)。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 眼镜 Surface 帧数 | 1196 | 1180 |
| 帧开始到呈现均值 / ms | 34.12 | 7.11 |
| 帧开始到呈现 P95 / ms | 45.99 | 11.11 |
| 呈现间隔均值 / ms | 16.67 | 16.94 |
| 呈现间隔 P95 / ms | 24.58 | 21.42 |
| 相对预期呈现时间均值差 / ms | 19.40 | -8.73 |
| 带 Buffer Stuffing 的帧数 | 1196 | 3 |
| RenderThread 在核运行 / s | 3.58 | 3.78 |

**本机样本支持 SBS 的额外呈现排队已明显减少。** 两者都有约 60 Hz 的输出节奏，优化后按实际内容更新提交，避免无条件循环填满队列。呈现间隔 P95 从 24.58 ms 降为 21.42 ms；不能只凭一次短轨迹声称所有流畅度都改善。

这里的帧开始到呈现时长不是 GPU 计算耗时，也不是触控到光子的端到端延迟。`Buffer Stuffing` 是厂商 FrameTimeline 分类；结合时长检查排队趋势，不换算成用户可感知卡顿率。每版只有一条短轨迹，长期热态、光学延迟和逐帧重复情况仍需单独测量。

## 外观、交互和恢复核验

数值记录见 [visual-validation.json](visual-validation.json)，解码器记录见 [codec-validation.json](codec-validation.json)。

- **模糊和动画定义保持：** 两版首页各有相同的 2 个眼镜循环和 2 个手机循环，持续时间与延迟一致。固定到 600 ms 相位的截图，在排除系统栏的手机区域，2D/SBS 分别有 99.996% / 99.996% 像素的每个通道差异不超过 1（8 位通道）。眼镜固定顶部区域约 99.994% 满足同一条件。媒体区内容在两次采集间改变，不能把整幅眼镜截图当成逐像素相等的证明；原始截图不入库。
- **淡出和恢复：** 真机看到音柱在 opacity 约 0.0058 时仍运行，opacity 到 0 后暂停且动画时间不再增长；恢复、快速打断退出和暂停视频都保持正确状态。触控提示在 opacity 约 0.0864 时仍运行，淡出完成后两条波纹暂停。与新增的异步回归测试相互核验。
- **两眼运动：** 优化版 HEVC 与 HLS 各 3 张外屏截图，按默认几何对齐 1824×1026 区域，完全相同像素约 99.86%–99.91%，通道平均绝对差小于 0.00050。相邻时点画面持续变化，排除双眼均冻结的情况。此结果不代表光学佩戴、眼序、逐帧音画同步的验收。
- **深度与大小：** 真机覆盖 90% 大小下深度 0–3，深度 1 下大小 80/85/90/95%，共 8 组。原 document/video/source 与 1440×810 DOM 视口均保持；原生设置和物理 SBS 状态符合请求。HLS 播放期间快速切换 5 次主题，PlaybackInfo、开始/停止请求计数不增加。
- **字幕与播放控件：** 另选兼容的 1080p SubRip 样本，实际加载 75 条字幕并显示文字；SBS 双眼图像、暂停/恢复和快进十秒通过。播放页 renderer 崩溃后双端恢复首页、硬件视频资源归零；见 [playback-regression.json](playback-regression.json)。
- **模式切换：** HEVC/HLS 的 2D→SBS 均保留 document/video/source，只有一个视频。系统仍会在 EDID 重建后关闭逻辑外屏；测试使用 `cmd display enable-display` 协助恢复。这一 HyperOS 行为未在本次修改中修复，不把切换时长当成完全自动或无黑屏切换的承诺。
- **恢复：** 前后台往返、冷启动会话与 simpleUI 偏好恢复、浏览页 renderer 崩溃后重建通过。记录见 [lifecycle-validation.json](lifecycle-validation.json)。设备拒绝 `WRITE_SECURE_SETTINGS`，无法启用“离开即销毁 Activity”进行强制重建测试；该系统设置保持原值，本项未覆盖。

## 构建、清理及后续建议

GlassesUI TypeScript、**25 个前端测试**、两端 production build、**80 个 JVM 测试**、Debug/Release lint、Debug/Release APK 组装及 `scripts/verify-android.sh` 通过。生成前端包随源码一并提交；未引入新运行时依赖、第二个播放器或 XR Space。

结束时已保留优化版安装，双端回到首页，恢复测试前的 **simpleUI、Mirror 2D、深度 1、大小 95%**，登录有效；硬件视频资源和 HTML video 均为 0。渲染器故障测试留下的本应用服务端播放/转码标记已补发停止上报清理，确认两者均为 0；这不代表故障时的服务端停止上报已自动修复。再次写回并读取，确认 **3/3 测试条目**的续播位置、已看状态和播放计数恢复。原先没有最后播放日期的条目可能保留本次测试的最近播放时间。临时网页探针和本地测试存储已移除；见 [cleanup.json](cleanup.json)。

后续优先进行相同视频的 10–20 分钟热态与非充电功耗测量，再针对 4K60 剩余丢帧定位 MediaCodec 到显示的帧去向。保留可见动效的前提下，液态玻璃首页仍需单独研究合成区域与缓存；本次未证明其主要开销已解决。MKV 重封装、极限码率、超大库和字幕压力建议仍保留，没有未经验证地缩短 HLS 缓冲或修改直放兼容策略。

本次不是完整发行验收：真实物理插拔、拒绝 USB 权限/占用接口、全部多账号/未授权恢复路径、位图字幕/HDR、逐眼光学听感及整套设备回归矩阵仍未全部覆盖。没有把 JVM 模拟结果替代这些未执行的真机项目。

## 复现

分别在独立工作树构建 `67662d5` 和本次源码，使用 `scripts/build-android.sh debug` 原位安装。按上述主题、模式、播放位置和预热条件，使用已有 [真机采样器](../../../scripts/measure-device-performance.mjs) 记录；不要在静态采样期间加入持续 rAF 探针。

FrameTimeline 使用 [本次配置](frame-trace.pbtxt)。ADB 推送到设备后，将配置经标准输入交给 Perfetto，避免本机 Perfetto 服务不能直接读取 `/data/local/tmp` 的限制。原始系统轨迹和真实媒体截图保持本地私有，只提交数值摘要。两版均使用相同配置和单独的采样窗口。
