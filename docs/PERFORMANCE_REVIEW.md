# 性能审阅与保持视觉效果的优化

审阅日期：2026-09-05；比较基线：`ea17589`。范围包括 Android、GlassesUI 和 CompanionUI。此次改动集中在 JavaScript 加载、搜索计算和重复渲染，保留现有布局、图片、模糊、折射、阴影、动画时序、图片质量和播放缓冲配置。

## 已完成的优化

| 位置 | 原有开销 | 本次处理 |
| --- | --- | --- |
| `GlassesUI/src/App.tsx` / `PlayerPage` | 首页入口静态引入整个 HLS 播放库，浏览和直放也需要解析它 | HLS 播放才动态加载；保留 worker、解码能力筛选、回退和缓冲设置。离开播放器或重新准备轨道后，过期的异步加载不能挂载媒体源 |
| `GlassesUI/src/seriesSearch.ts` / `buildSeriesIndex` | 动态 import 之后仍连续同步生成所有拼音，阻塞输入与动画；重新进入搜索会再次计算 | 每约 8 ms 主动让出事件循环，支持取消；用 WeakMap 复用未变化的媒体对象，不以 ID 跨会话保存索引 |
| `GlassesUI/src/App.tsx` / 搜索数据选择 | 完整索引未返回时，每次父组件渲染都创建新的备用数组，触发索引 effect 重跑 | 按原始媒体数组记忆化备用列表；离开搜索时取消尚未完成的索引计算 |
| `GlassesUI/src/seriesSearch.ts` / `searchSeries` | 每部剧重复规范化同一个查询，排序时重复请求中文比较器 | 每次查询只规范化一次，复用 `Intl.Collator('zh-CN')`；匹配规则、推荐加权、排序、数量限制与季集提示保持一致 |
| `GlassesUI/src/App.tsx` / `moveFocus` | 同一个方向键处理期间先读取全部元素矩形，再重复读取候选矩形 | 在该次按键内复用矩形；下一次按键重新测量，仍跟随滚动、尺寸和动画变换 |
| `GlassesUI/src/App.tsx` / `MediaCard` | 仅背景预览或首页焦点区域改变时，所有未变化卡片仍执行渲染 | 使用 React `memo`，保留原来的 DOM、CSS、焦点事件和更新后的媒体状态 |

## 测量结果

搜索基准使用 10,000 部合成剧集，含中文名、英文名、别名、日期、收藏和进度；运行环境为 macOS ARM64、Node.js 24.13.0。以下是一次本机对比运行，不能换算成 Android 真机帧率或功耗。拼音模块先预热，索引耗时不含模块首次加载；查询统计包含 16 种查询各执行 7 次。

| 指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 首页入口 JavaScript，未压缩 | 892.03 KB | 299.60 KB |
| 首页入口 JavaScript，gzip 参考值 | 280.77 KB | 95.23 KB |
| 首次构建索引 | 182.18 ms | 170.62 ms |
| 构建期间最大事件循环间隔 | 182.18 ms | 9.77 ms |
| 相同媒体对象再次构建索引 | 149.25 ms | 1.43 ms |
| 查询耗时中位数 | 6.70 ms | 4.35 ms |
| 查询耗时 P95 | 18.84 ms | 15.88 ms |

入口 JavaScript 减少约 66.4%。HLS 代码仍随 APK 分发，约 592 KB 的独立 chunk 在需要 HLS 时才加载，因此这是启动解析工作量的下降，并非 APK 同比例缩小。首次 HLS 播放增加一次本地模块加载。8 ms 是在媒体条目之间检查的计算预算，不是硬实时上限；单个超长标题、GC 和模块加载仍可能超过它。

在浏览器演示首页的 8 次方向键操作中，矩形读取总数从 637 次降至 408 次，焦点路径完全一致。在主视觉与内容行之间切换时，单次封面及背景 URL 构造从 38 次降至 1 次，反映了未变化卡片的重复渲染被跳过。

## 视觉与行为验证

- 两端 CSS 和所有图片文件与基线逐字节相同。
- 隔离 Chromium 以演示数据比较眼镜端首页、搜索、媒体库、详情页（1920×1080）和手机连接页（390×844）。动画固定到相同时间点后，Pixelmatch `threshold=0.1` 的差异像素均为 0；严格阈值下前三页分别有 4、13、24 个像素差异，详情与手机连接页为 0。此结果支持没有可见视觉变化，不代表所有设备逐像素一致。
- 200 种查询 × 3 种结果上限，共 600 组对比的条目、顺序、分数和匹配原因完全一致，生成的索引内容也一致。
- 7 个前端回归测试覆盖中文、英文、拼音、首字母、别名、模糊匹配、季集提示、推荐排序、数量边界、对象替换和异步取消。
- 使用本地合成 H.264/AAC 视频验证直放和 HLS。两条路径都只有一个 `<video>`，开始和停止各上报一次，暂停可用；直放不请求 HLS chunk，HLS 只加载一次。
- 覆盖完整索引延迟返回时的备用搜索，以及 HLS chunk 尚未返回时退出播放器的取消行为；另验证切换字幕并延迟新播放计划返回时，旧源保持脱离，新计划就绪后可恢复播放并显示字幕。
- TypeScript、两套 production build、7 个前端测试、39 个 JVM 测试、Debug/Release lint 与 APK 组装通过；两个 APK 均通过 `verify-no-unity.sh`。Debug 约 7.0 MiB，未签名 Release 约 6.7 MiB。

## 其余性能评估

| 区域 | 现状与后续优先级 |
| --- | --- |
| Android 会话与桥接 | 已有原生/前端状态去重、单一会话源和有界遥控队列，未发现需要增加轮询或副本的理由。继续保留 |
| 手机触控板 | 光点直接更新 transform，运动稳定后停止 rAF；指针几何也已有缓存。主要剩余成本应通过 GPU/绘制跟踪确认 |
| 玻璃效果与背景 | 两端有大范围 blur、backdrop-filter、SVG 折射和持续动画，属于潜在 GPU 热点。尚无设备 GPU 轨迹证明具体耗时，本次保留全部效果。下一步测量重绘区域与图层内存，再评估保持相同溢出范围的绘制隔离 |
| SBS 合成 | 一个 WebView、一个视频，原生每帧绘制左右眼。不能仅因存在持续 invalidate 就删掉它或降低刷新率；需真机确认视频纹理与动画的双眼同步 |
| 播放与字幕 | `timeupdate` 更新整个播放器，并线性扫描当前字幕 cues。长字幕文件值得后续分析；优化应保留重叠字幕、回退 seek、控制栏动画及上报时序 |
| 大媒体库网络 | 首页并发等待 6 个响应；目录最多 500 项，完整 Series 索引按 200 项请求、上限 50,000。可继续评估过期请求取消、按需加载详情字段和服务端分页，需单独验证列表内容、顺序及焦点恢复 |
| HLS 内存 | 前向和后向缓冲会影响内存与网络恢复能力。本次保持原配置；先用长片实测 WebView/解码器内存、GC 和丢帧，再决定是否调整 |

当前没有连接 Android 测试设备，尚未执行 `ANDROID_ARCHITECTURE.md` 的真机回归矩阵。发布前仍需覆盖连接/断开、2D/SBS 切换及失败回退、轨道切换、字幕、renderer 恢复、登录退出和单音频/单上报，并记录代表性媒体的实际 MediaCodec、帧耗时、内存和功耗。浏览器验证不能替代这些硬件结论。

## 复现

从仓库根目录运行：

```bash
npm --prefix GlassesUI test
npm --prefix GlassesUI run benchmark
```

比较本次审阅前后的搜索行为与性能：

```bash
performance_baseline=$(mktemp)
git show ea17589:GlassesUI/src/seriesSearch.ts > "$performance_baseline"
npm --prefix GlassesUI run benchmark -- "$performance_baseline"
rm "$performance_baseline"
```

基准只生成合成媒体对象，不启动开发服务器，不读取 `.jellyfin-dev.json`，不访问真实 Jellyfin。完整 Debug 验证入口仍是 `./scripts/build-android.sh debug`，现在也包含上述前端回归测试。
