> 目标：让另一名 AI 在不访问原实例的情况下，能够重建本次调查所见的 Jellyfin Web 信息架构、页面内容、视觉层级和交互状态。

## 1. 文档边界与可信度

本文记录的是一个真实 Jellyfin 实例在简体中文、Dark 主题、桌面视口下的快照，不是 Jellyfin 官方所有版本的通用产品说明。

调查方式与边界：

- 实际登录指定测试账号并逐页浏览。
- 采样视口为 `1280 × 720`，设备像素比 `1`。
- 只进行了导航、搜索、展开菜单、分页和进入临时多选状态。
- 未播放媒体，未新增或删除播放列表/合集，未改变收藏或已观看状态，未保存任何设置。
- 播放器、实际投屏、同步播放群组创建、忘记密码结果页和错误登录提示没有触发，以免改变服务器状态。
- 测试账号不是管理员，因此控制台、媒体资料管理器、任务、插件、服务器日志等管理页面不在本次范围内。
- 非管理员界面没有“关于”入口；尝试 `#/about` 和 `#/dashboard/about` 均得到“未找到页面”，所以无法从 UI 确认服务器或 Web 客户端版本。
- 窄屏没有进行真实视觉采样。本文给出实际 CSS 中出现的断点，但移动布局只能作为待验证项。

### 1.1 数据分类

实现时必须区分以下三类状态：

| 标记 | 含义 | 示例 |
| --- | --- | --- |
| 固定 UI | Web 客户端结构或文案，通常不随媒体数据改变 | 顶栏、菜单、筛选器、设置字段 |
| 服务器动态 | 来自媒体库与元数据，可在扫描后变化 | 标题、海报、年份、简介、演职人员、总数 |
| 用户动态 | 由当前账号状态决定 | 已观看、收藏、继续观看、建议、未看数量 |

复刻时不应把本次快照中的电影数量、结束时间或建议项硬编码到固定组件中；它们应由数据模型驱动。

## 3. 路由与信息架构

用 `BASE = http(s)://<server>:<port>/web/` 表示部署地址。内部 ID 必须从服务端数据取得，不能复制本实例的值。

| 页面 | Hash 路由模板 | 说明 |
| --- | --- | --- |
| 首页 | `#/home` | 首页与全局我的最爱 |
| 电影 | `#/movies?topParentId={libraryId}&collectionType=movies` | 电影专用多页签页面 |
| 电视剧/番剧/国创 | `#/tv?topParentId={libraryId}&collectionType=tvshows` | 三个库共用同一 TV 页面模板 |
| 通用文件夹/合集库/网课 | `#/list?parentId={folderId}&serverId={serverId}` | 文件夹、集合与普通视频混排 |
| 媒体详情 | `#/details?id={itemId}&serverId={serverId}` | 电影、节目、季、集、合集、普通视频复用 |
| 搜索 | `#/search`、`#/search?query={encodedText}` | 输入后实时更新 query |
| 设置目录 | `#/mypreferencesmenu` | 用户按钮直接进入此页，不是浮层菜单 |
| 个人信息 | `#/userprofile?userId={userId}` | 头像与密码 |
| 快速连接 | `#/quickconnect?userId={userId}` | 输入设备验证码并授权 |
| 显示 | `#/mypreferencesdisplay?userId={userId}` | 语言、主题、显示、媒体库显示选项 |
| 首页设置 | `#/mypreferenceshome?userId={userId}` | 首页模块和媒体库顺序 |
| 播放设置 | `#/mypreferencesplayback?userId={userId}` | 音视频、分段与转码偏好 |
| 字幕设置 | `#/mypreferencessubtitles?userId={userId}` | 字幕选择和外观 |
| 操控设置 | `#/mypreferencescontrols?userId={userId}` | 游戏手柄开关 |
| 未知路由 | 任意不存在的 hash | 独立的“未找到页面”页，含说明和“返回主页”链接 |

### 4.1 桌面顶栏

- `position: fixed`，`z-index` 高于页面内容。
- 一级库页面和首页使用双层顶栏，总高 `110.34375px`：
  - 工具栏高 `57.578125px`；上下 padding 约 `8px`。
  - 页签条高 `52.765625px`。
- 图标按钮为 `41.375 × 41.375px`，圆形命中区域，内部 padding `8.27328px`。
- 页签文字约 `12.4248px`、`font-weight: 600`，每个页签 padding `18.6372px`；活动页签文字更亮并有青色状态线。
- 首页左侧是菜单和 Jellyfin 渐变三角 Logo/字标；如果浏览历史可返回，会额外显示返回按钮。
- 内页左侧依次为返回、首页、菜单、当前页面标题；详情页不显示二级页签。
- 右侧固定顺序：同步播放、投屏、搜索、当前用户。

### 4.2 侧边抽屉

- 宽 `320px`，高为整个视口，`position: fixed`，底色 `#101010`。
- 关闭时实际矩形为 `x=-320, width=320`；打开时滑至 `x=0`。
- 桌面端打开后覆盖页面左侧，不挤压内容，也不额外降低正文亮度。
- 抽屉自身可纵向滚动；每行带左侧图标和文字。
- 当前测试账号的项目严格如下：
  - 首页
  - 分组标题“媒体”
  - 电视剧、电影、番剧、国创、合集、网课
  - 分组标题“用户”
  - 设置、退出
- 管理员常见的“控制台”“媒体资料管理器”没有出现；复刻必须按权限隐藏，而不是禁用显示。
- 打开状态可跨路由保留；详情页左侧海报会被抽屉遮住一部分。

### 4.3 页面滚动与内容区域

- 主页面是全屏绝对定位容器，双层顶栏页的顶部 padding 为 `111.6px`，底部留白约 `74.4px`。
- 内容纵向滚动；首页每个分区内部是横向卡片流。
- 页面标题、分区标题和卡片流从约 `3.3vw` 开始。
- 有 A–Z 索引时，卡片容器右侧额外预留 `96px`。
- 分区标题字号 `22.32px`，`font-weight: 400`；一个典型标题行高约 `45.72px`，左 padding `42.23px`。
- 图片使用懒加载、BlurHash 占位和快速淡入。没有主图时显示蓝青色矩形和白色场记板图标。

## 5. 通用组件规格

### 5.1 媒体卡片

桌面电影网格（1280 宽）每行约 6 张：

| 部分 | 实测尺寸 |
| --- | --- |
| 卡片占位 | `190.28125 × 333.6875px` |
| 海报卡片盒 | `172.4375 × 315.84375px` |
| 海报图片 | `172.4375 × 258.65625px`，精确 2:3 |
| 卡片盒外边距 | 上下 `8.928px`、右 `17.856px` |
| 图片圆角 | 顶部约 `3px`；卡片模式下底部由信息区承接 |

首页尺寸略大：

| 类型 | 外占位 | 实际图片 |
| --- | --- | --- |
| 媒体库横幅卡 | `295.671875 × 218.46875px` | `277.828125 × 156.265625px`，约 16:9 |
| 最近添加海报卡 | `198.390625 × 352.75px` | `180.546875 × 270.8125px`，2:3 |

卡片状态：

- 默认显示主图、标题以及年份或年份范围。
- 电视剧/番剧海报右上角可显示蓝色圆形未看集数徽标。
- 合集右上角用同样徽标显示包含项数量。
- 长标题单行截断并显示省略号。
- 鼠标悬浮时图片覆盖半透明黑色层，中心出现播放按钮，底部动作区依次为：标为已播放/已观看、加入收藏、更多。
- 已看内容的状态按钮文案变为“已观看”，图标也使用已选中状态。
- CSS 明确包含 `(hover: hover) and (pointer: fine)` 条件；触摸复刻不能依赖 hover 才能进入详情或操作。

### 5.2 卡片“更多”菜单

以电影卡片为例，菜单顺序为：

1. 播放
2. 从这里开始全部播放
3. 选择
4. 添加至播放列表
5. 媒体信息

菜单是贴近触发卡的深色浮层，图标在左、文案在右，页面其余区域变暗。不同项目类型可以少一项或换成相应动作。

### 5.3 多选模式

选择某一卡片后：

- 普通顶栏被一条高约 `71px` 的整宽品牌青色栏替代。
- 左侧为关闭 `×` 和已选数量；右侧为三点菜单。
- 每张卡片出现左上复选框和青色细描边；当前项打勾。
- 批量菜单依次为：全选、加入集合、添加至播放列表、标为已播放、标为未播放。
- 关闭多选只清除临时选择，不应改变服务器数据。

### 5.4 横向媒体流

- 首页、详情页演职人员、相似内容、搜索结果使用横向流。
- 标题右侧或行的最右端放置上一页/下一页箭头。
- 到达起点时“上一个”禁用；后方仍有内容时“下一个”启用。
- 搜索结果和详情相关推荐允许内容超出右边界并水平推进，不换成纵向分页。

### 5.5 A–Z 索引与分页

- 固定在屏幕最右侧的竖向 `# A B … Z` 列，实测区域 `x=1245.05, y=83.08, width=20.97, height=567px`。
- 单击字母跳到或筛到对应首字母，不改变排序菜单的设置。
- 分页文案格式为“`总数 的 起始-结束`”，例如“120 的 1-100”。
- 分页区含向前/向后圆形箭头；第一页禁用向前，最后一页禁用向后。
- 同一个分页控件可同时出现在列表顶部和底部。

### 5.6 表单和主按钮

- 输入框实测高度约 `39.09px`，底色 `#292929`，边框同色，文字 `16.368px`。
- 青色主按钮高度约 `46.86px`，白字，padding `13.392px 14.88px`，圆角约 `3px`。
- 设置页控件通常占内容列整宽；标签在控件上方，帮助文本在下方。
- 复选框选中时为青色方块和白色对勾，未选中为透明/深色方块和浅色描边。
- 所有设置都依赖显式“保存”；调查中没有触发保存。

## 6. 登录页

未登录访问 Web 时进入居中的登录表单。

固定内容：

- 标题“请登录”。
- “用户”文本字段。
- “密码”密码字段。
- 默认勾选“记住我”。
- 青色主按钮“登录”。
- 次级按钮“使用 Quick Connect”。
- 次级按钮“忘记密码”。

成功登录后进入首页。复刻时不要把本次测试密码写入源码、文档、测试夹具或默认值。

## 16. 交互状态机

### 16.1 认证

```text
未认证 → 登录页
登录成功 → 首页
退出 → 清除当前会话并返回登录页
快速连接 → 输入验证码 → 授权（本次未执行）
```

### 16.2 卡片

```text
默认
├── 点击图片/标题 → 详情或下一级文件夹
├── hover → 动作遮罩
│   ├── 播放 → 播放器
│   ├── 已观看 → 切换用户状态
│   ├── 收藏 → 切换用户状态
│   └── 更多 → 上下文菜单
└── 未看/数量数据存在 → 右上徽标
```

### 16.3 搜索

```text
进入搜索 → 自动聚焦
空字符串 → 建议文本列表
输入变化 → debounce 请求 → URL query 更新 → 按类型渲染横向结果
清空 → 回到建议
点击结果 → 对应详情页
```

### 16.4 详情

```text
载入 item
├── 有背景/海报/Logo → 详情 Hero 布局
├── 普通视频 → 横向缩略图的精简布局
├── 轨道数 = 1 → 禁用下拉
├── 轨道数 > 1 → 可选音频/字幕/版本
├── 更多 → 添加至播放列表 / 媒体信息
└── 下滚 → 演职人员 / 场景 / 同季 / 相似内容（按类型选择性出现）
```

### 16.5 临时层级优先级

从低到高：页面内容 → 固定顶栏/A–Z → 抽屉或卡片菜单 → 对话遮罩 → 同步播放/投屏面板 → 多选顶栏。打开新的顶层弹层时应先关闭旧弹层，避免重叠。

## 17. 可访问性观察

正面观察：

- 顶栏图标都有中文可访问名称：返回、首页、菜单图、同步播放、投屏、搜索、用户名。
- 卡片动作都有明确名称；节目、季和集标题均是可聚焦链接。
- 页面使用 H1/H2/H3/H4 建立标题层级。
- 下拉框暴露当前值和展开动作，复选框暴露选中状态。
- 禁用的上一页按钮和单轨下拉能被辅助技术识别为 disabled。
- 焦点/活动状态使用明显青色。

需要在复刻中改善或忠实处理的缺陷：

- 搜索输入在无障碍树中主要暴露内部 ID `searchTextInput`，可见 placeholder 为“搜索”，最好补明确 `aria-label="搜索"`。

- 空“我的最爱”没有状态文本；如果追求像素级复现可保持空白，如果追求可访问性应加屏幕阅读器专用提示。
- 次要文字为 80% 白色，叠加背景图和遮罩时需再次检查 WCAG 对比度。
- 很长的标签与标题依赖截断；必须用 `title`、可访问名称或详情页提供完整文本。

## 19. 当前数据异常与复刻原则

当前实例存在明显元数据污染；这是页面快照的一部分：

- 电影第一页有 18 个同名 `Paprika`，全部显示年份 1959；另有一个文件名式 Paprika 条目显示 2006。
- 两个 Berserk 黄金时代文件名条目显示年份 1920。
- 电影名混合规范中文名、英文名、发布组前缀、编码参数和文件扩展信息。
- 电视剧“漂白”显示 `2025 - 2016`，“企鹅人”显示 `2024 - 2008`，年份范围倒置。
- 番剧“剑风传奇 次篇”显示 `2017 - 1998`。
- 同一库有重复节目，如两份“攻壳机动队 STAND ALONE COMPLEX”、两份“JOJO的奇妙冒险 石之海”、两个年代的“猫眼三姐妹”。
- 星球大战合集包含两个明显无关项目，而搜索命中的星战电影并不全部在该合集详情中。
- 《阿甘正传》标签混入另一作品的中文标签。
- 《黑袍纠察队》季/单集原始标题与剧情不匹配。
- 某些未来项目只有结束年份或空年份，UI 会显示 `- 现在` 或完全不显示年份。

正确复刻原则：前端负责稳健展示和截断，不对服务端元数据做推断修复。若要提供“清理元数据”功能，它必须是独立的管理工作流，不能悄悄改变浏览页。

## 附录 D：建议的数据接口形状

另一名 AI 若要实现高保真假数据层，至少应提供：

```ts
type UserState = {
    played: boolean;
    favorite: boolean;
    resumable: boolean;
    playbackPositionTicks?: number;
    unplayedItemCount?: number;
};

type MediaCard = {
    id: string;
    type: "Movie" | "Series" | "Season" | "Episode" | "BoxSet" | "Folder" | "Video" | "Person";
    name: string;
    originalTitle?: string;
    productionYear?: number;
    endYear?: number;
    status?: string;
    primaryImage?: string;
    backdropImage?: string;
    logoImage?: string;
    overview?: string;
    officialRating?: string;
    communityRating?: number;
    criticRating?: number;
    runtimeTicks?: number;
    childCount?: number;
    seriesName?: string;
    seasonName?: string;
    indexNumber?: number;
    parentIndexNumber?: number;
    userData: UserState;
};

type MediaSource = {
    container: string;
    size?: number;
    videoStreams: VideoStream[];
    audioStreams: AudioStream[];
    subtitleStreams: SubtitleStream[];
    imageStreams?: ImageStream[];
};
```

关键渲染逻辑：

- 只渲染数据存在的分区，空首页模块直接省略。
- “年份 - 现在”来自开始年份和连续状态；不要把“现在”存成数值。
- 预计结束时间由当前客户端时间和剩余时长计算。
- 同名项目必须按 ID 区分。
- 轨道选择由媒体源和流列表生成；只有一项时禁用。
- 图片 URL 必须支持尺寸、质量、缓存标签和失败占位。
- 搜索和库分页由服务端总数、起始索引和限制驱动。
- 菜单能力应由项目类型、用户权限和服务端能力决定。
